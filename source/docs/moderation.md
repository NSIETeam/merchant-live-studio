# 现场记录与暂停处置

管理员、审核人员可以在「直播现场 → 现场处置」记录问题、证据位置及现场更正，或暂停直播。编辑/主播可读取记录，不能通过处置接口变更状态。所有接口验证直播间所属商家。

暂停立即在事务中写入不可改写的处置记录、结束本场、更新推流密钥、停止有效观看计时。随后关闭仍有效的演示红包活动并尝试断开媒体推流。没有有效的媒体控制响应时显示失败；不会仅凭数据库状态或发出请求就标为断流成功。

暂停期间，无论开发或生产配置，重新开播都被服务端拦截。断流失败可以重试；每次结果追加保存。只有当前暂停的处置可以重试，已解除的旧处置不能再次断开新直播。重复提交键返回同一记录，不重复执行。服务中断后，暂停仍持久化；没有成功结果时需要重试，不会自动解除。

恢复资格必须由另一个管理员/审核账号填写复核说明，并确认当前处置已得到成功断流结果。与发起暂停相同的账号不能自审解除。解除不自动开播，正式开播仍需通过其他准入检查。

接口：

- GET /api/merchant/rooms/:id/moderation：当前暂停及最近处置，默认 50 条，nextBefore 翻页。
- POST /api/merchant/rooms/:id/moderation：kind=note/stop/release、note、evidenceReference、idempotencyKey；release 额外携带当前 holdId。
- POST /api/merchant/rooms/:id/moderation/:actionId/retry：重试当前暂停的媒体处置。

迁移 v15 新增 moderation_actions、moderation_results；应用数据库触发器禁止修改或删除原记录。失败重试的旧结果在数据库保留，当前界面展示各暂停记录的最新执行结果，完整尝试记录导出待补。

本模块是人工现场管理，不是自动语音识别或违规判定。商品、公示或授权撤回尚未自动触发此处置；运营人员应主动核对并暂停。现有流媒体鉴权和控制仍有分布式时序边界，需要监控与真实环境持续验收。

## 本轮验证

139 项自动测试、构建和 HTTP 冒烟通过，覆盖越权、跨商家、暂停持久化、密钥更新、活动关闭、幂等、断流失败与重试、自审恢复拒绝、旧记录不能操作新直播、不可改写历史。

另在本机隔离端口使用官方 MediaMTX v1.21.0（Darwin ARM64，发行包 SHA-256：159b8e8164022189e654b61ee8bb7edf2d3ff9354ff06cf4c315bb59f5cc9eca）及 FFmpeg 7.1 推送 H.264/AAC 合成视频：

- 浏览器连接 HLS；独立解码器读取到 30 帧 / 2 秒有效视频。
- 通过工作台暂停后，真实 RTMP 发布连接终止，两个 HLS 阅读连接被关闭，控制 API 的媒体路径返回 404。
- 观众页显示直播结束，重新准备后再次开放被服务端拒绝。
- 另一审核账号在浏览器复核解除，保留原处置与复核记录。
- 同轮产生的 7 个 fMP4 录像均可解码，约 62.5 秒。仅证明录制引擎输出，平台录像检索、访问权限、长期容量与备份仍未完成。
