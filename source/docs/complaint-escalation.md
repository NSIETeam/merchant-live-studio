# 投诉时限与独立申诉功能卡

归属模块 `review`。现有投诉受理继续由商家管理员处理；新增可见的内部处理时限，以及观众对已答复投诉发起一次申诉、由独立审核员复核的闭环。该时限是平台内部服务目标，不冒充法定期限或审核结论。

投诉收到后 24 小时内应首次进入处理中或已答复；接口返回 `responseDueAt` 与 `overdue`，商家和观众看到同一口径。申诉提交后 48 小时内应答复，并返回 `reviewDueAt` 与 `overdue`。时间均由服务端时钟计算，不依赖浏览器时间；超时只形成醒目标记，不自动伪造处理结果。

观众仅能对自己的、已经答复的投诉提交一次申诉。提交包含 5–2000 字理由和 UUID 幂等键；重复同一请求返回原申诉，变更内容后复用编号返回冲突。申诉原文、状态事件、处理人和时间不可改写或删除。浏览器会话丢失后的身份恢复仍依赖后续实名方案。

管理员可以查看原投诉及申诉，但当商家需要独立复核时，只有审核员能首次受理申诉，且不能与原投诉最后答复人相同。审核员可追加“复核中”或“复核完成”回执；客户端带上一版本，过时写入返回冲突。审核员只能访问所属商家的投诉，不能处理原投诉或管理团队。

新增迁移 v20：`complaint_appeals` 与 `complaint_appeal_events`，均由 `review` 所有并设不可更新、不可删除触发器。部署必须先备份数据库并完成恢复检查；本功能不删除既有投诉，也不发送外部短信、邮件或微信通知。

验收覆盖：时限边界、仅已答复可申诉、一次申诉与幂等冲突、跨观看会话和跨商家隔离、管理员不能替代独立审核员、原处理人不能复核、版本冲突、不可改写、重启持久化、桌面及 390 像素页面无横向溢出。

2026-09-11 本地实现与验收：完整投诉接口测试覆盖上述服务端边界，数据库重开后仍保留 1 项申诉及 3 条最终为“复核完成”的事件。浏览器实际完成观众提交投诉、管理员答复、观众申诉、托管审核账号登录并独立复核；观众抽屉和审核工作台在 390 像素宽度均无横向溢出，未出现绿色界面。实看发现并修复了观众白底投诉卡片文字对比度过低的问题。此增量尚未部署，随下一批统一发布。
