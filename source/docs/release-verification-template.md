# 发布验收记录：填写版本或变更名称

每次发布复制本模板，在发布记录、Issue 或 PR 中选一处维护。发布前填写计划和已有证据，发布后补充实际结果；状态使用“待验证、通过、失败、被阻止、跳过、已回滚、不适用”，不适用需说明原因。记录不得包含凭据、会话、客户原始资料或完整模型输入。

## 发布前

- **目标**：目标环境、完整提交 SHA、所含功能卡或 PR。
- **检查与产物**：该版本的 CI 链接及结果、构建配置、产物标识或 SHA-256，以及部署后核对产物的方法。
- **迁移条件**：旧版本与数据模式、此次迁移及数据保留校验、资源和配置前置条件；无迁移时说明。已发布迁移不得覆盖改写。
- **备份与恢复**：备份范围、执行时点、完成判据、受限存储位置，以及适用的恢复验证证据。发布前准备安排；本次备份成功后再填写实际位置。
- **健康与关键流程**：Live/Agent 健康、首页及相关用户流程的检查方式和成功判据；确认部署要求的直播空闲条件。
- **回滚路径**：旧版本、触发条件、操作方式、数据及配置兼容条件、恢复后的核验方式；不能仅假定切回代码就能还原数据。

## 发布后

- **执行结果**：工作流或受控部署记录、执行时间、状态、失败或跳过原因及后续处理。
- **实际版本与产物**：服务器报告的运行 SHA、与目标 SHA 的对照、产物一致性证据。未能确认时标为待验证，不能填目标 SHA 充当实测结果。
- **实际备份**：本次成功备份的标识或位置、范围及校验结果；若在备份前被阻止，明确记录“未执行”。
- **健康与流程结果**：Live/Agent、首页和所选关键流程的实际结果；是否解除维护、是否发生回滚及恢复后的版本与健康状态。
- **真实能力验收**：涉及的真实模型、微信、资金或推流，分别记录环境、版本、场景、结果和证据；仅模拟、未配置或未验证时明确标识。引用旧证据时说明其适用范围及本次变更是否影响它。
- **交付状态**：目标版本已部署并验证 / 部署后待验证 / 被阻止 / 跳过 / 失败 / 已回滚；未完成项和处理人或后续事项。

现有自动部署流程及其检查范围见[自动部署说明](automatic-deployment.md)。仅当目标版本、产物及所需健康和关键流程验证完成后，才可填写“目标版本已部署并验证”；真实外部能力的验收单独报告。
