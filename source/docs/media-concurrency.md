# 真实 HLS 并发传输核对

执行脚本会创建独立临时目录、回环端口和 MediaMTX 进程，通过 FFmpeg 推送合成竖屏 H.264/AAC 视频；不会使用现有业务房间或向公网地址施压。所需二进制由操作者提供，不自动下载。

```sh
node scripts/media-concurrency-smoke.mjs \
  --clients=100 \
  --mediamtx=/absolute/path/to/mediamtx \
  --ffmpeg=/absolute/path/to/ffmpeg
```

客户端数量允许 1–200。每路读取 4 轮播放列表及最新分片，要求至少两个不同分片证明媒体推进；检查 MPEG-TS 长度与同步字节，并使用 FFmpeg 解码一个样本。结束后停止本脚本创建的进程，清理临时目录，输出 JSON。任何客户端检查失败都会使总体失败。

## 2026-09-11 本机结果

MediaMTX 1.21.0，FFmpeg 7.1，360×640、15fps 合成画面与测试音：

- 100 路客户端、800 次请求通过，共读取 77,392,600 字节。
- 4 个不同媒体分片，每个客户端均读到持续推进的分片。
- 请求 p95 48.21ms，采样阶段约 3.8 秒。
- 抽样分片实际解码成功，临时进程与文件清理完成。

这是同一机器上的短时传输验证，不含平台鉴权、浏览器渲染、真实主播设备、公网链路、CDN、微信真机、支付或长时间稳定性。平台资格/鉴权与 Agent 故障隔离分别由既有接口和真实开停播用例验证，不因本结果自动成为整条生产链路验收。生产容量仍需按服务器、分辨率/码率与目标在线人数另行核定。
