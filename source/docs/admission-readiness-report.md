# 功能卡：开播提审准备报告

- **所属模块**：`live` 汇总自身房间、媒体控制和已注入的公示/定稿准入结果；前端直播现场提供下载入口。报告不跨表读取 review/content 数据，也不替代各模块的原始记录。
- **用户验收场景**：商家选择直播间后可重新执行开播检查并下载同一时点的 JSON 报告，交给内部审核或用于定位待补材料。报告明确区分技术准备状态与真实资质结论，包含房间、生成时间、逐项结果和本次依据版本。
- **接口变化**：新增商家接口 `GET /api/merchant/rooms/:id/admission-report`，返回附件 `studio-admission-<roomId>.json`；内容含格式版本、范围、房间摘要、完整 `AdmissionCheck` 与限制说明。
- **数据变化与权限**：只读、无数据库变化。必须是当前租户房间并通过既有角色访问控制；站外租户返回 404。报告不包含推流密钥、账号密钥、联系方式全文、商品事实正文、讲稿正文、观众或资金记录。
- **失败处理**：每次下载重新检查媒体控制和当前授权状态；外部控制不可达时报告对应检查失败，不使用旧结果伪报通过。房间不存在/不属于当前商家时不生成附件。

## 随实现补充证据

- **流程结果**：直播现场的折叠“开播准备检查”同时提供重新检查和下载入口。下载重新执行授权同步、媒体控制探测及六项准入检查，返回时点快照、版本依据和三条边界说明；未准备好的演示房间如实返回 `ready:false`。
- **专项验证**：自动测试实际下载 JSON，核对附件文件名、no-store、房间摘要、检查结果、限制说明、跨租户 404，以及会话/推流秘密不出现在报告中。真实 Chrome 已在 1280×900 与 390×844 打开直播现场和该折叠项，入口可见且同会话下载返回 200；两种视口横向溢出与绿色元素均为 0。
- **基础检查**：完整 `npm run check` 通过 207 项业务测试、架构和数据归属门禁、类型检查、生产构建及 HTTP 冒烟；高等级依赖审计为 0 个漏洞，部署脚本 9 项测试通过。
- **阶段状态**：本地软件候选完成，留待下一次集中发布。报告不包含真实材料原件，未配置项目继续显示待补齐，因此不构成资质审核通过。
