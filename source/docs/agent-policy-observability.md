# 功能卡：直播 Agent 系统策略与决策可观测性

## 实现前填写

- **所属模块**：主模块为 `agent`；Web 端仅展示 Agent 服务公开返回的运行信息。`knowledge` 继续提供已审核事实，`live` 继续提交房间上下文，两者不新增写入。
- **用户验收场景**：运营人员进入直播 Agent 工作台时，可以看到当前固定系统策略版本、短指纹、模型服务状态与已配置的思考强度。运行一次彩排或直播建议后，可以查看证据筛选、合规规则、模型编排与最终引用四类结构化决策记录，判断结果为什么可用或为什么回退；界面不得展示或声称展示模型私有思维链。本阶段不接入具体模型密钥，也不允许模型自由补写商品事实。
- **接口变化**：Agent 服务状态增加可选的 `systemPolicyVersion`、`systemPolicyFingerprint`、`reasoningEffort`；Agent 结果增加可选的 `systemPolicyVersion`、`systemPolicyFingerprint`、`reasoningEffort` 与 `decisionTrace`，以兼容已有持久化结果。OpenAI 兼容请求仅在显式配置时发送标准 `reasoning_effort` 字段。运行接口、超时、队列和幂等契约不变。
- **数据变化**：不新增表、不迁移数据库。策略版本、指纹和决策轨迹随现有不可变运行结果 JSON 保存，由 `agent` 模块所有；旧结果字段缺失时前端显示“历史结果未记录”。
- **权限**：沿用商家 Agent 工作台、租户和房间权限；公开观众接口不返回策略、提示词或决策轨迹。环境变量只能由服务端读取，前端不接触端点或密钥。
- **失败处理**：思考强度配置非法时服务启动失败；未配置真实模型时明确显示本地规则，不伪装成深度模型输出。模型超时、通信失败或结构校验失败继续回退本地规则，并在轨迹中记录公开的失败阶段和回退结果，不记录内部异常、密钥或模型思维链。

## 随实现补充证据

- **流程结果**：Agent 健康状态和新运行结果均返回固定策略版本/指纹；显式配置的思考强度进入兼容模型请求并写入结果；每次运行生成五步公开轨迹。工作台可以看到服务策略信息，并能在完成的试演中展开查看轨迹。开发模式首页原有的 React 初始化白屏一并修复。
- **基础检查**：未提交工作区于 2026-09-12 完整运行 `npm run check` 通过：30 项架构/数据所有权测试、227 项业务测试、类型检查、生产构建和构建后 HTTP 冒烟均通过；`git diff --check` 通过。尚无对应提交或 CI。
- **专项验证**：`tests/agent-core.test.ts` 覆盖指纹、五步轨迹、模型请求中的思考强度及远程/本地标识；`tests/agent-service.test.ts` 覆盖配置允许值、非法值和健康状态；`tests/agent-gateway.test.ts` 覆盖安全元数据跨私有桥接。真实浏览器在本地开发服务完成演示登录、进入“表达与提示词”、运行一次试演并展开五步轨迹；桌面 1264×715 可用。Chrome 以 390×844 移动视口复验，`scrollWidth === innerWidth === 390`，无横向溢出，页面显示 `live-planner-2026.2#8da36b848f73`。
