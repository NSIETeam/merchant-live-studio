# 功能卡：营销方案比较与执行建议

## 实现前填写

- **所属模块**：主模块为 `marketing`；通过已注入公开接口读取 `knowledge` 的商品证据版本与 `content` 的课时/讲稿状态。Web 入口位于商品与课程工作台。Agent、直播、审核和资金模块不被写入。
- **用户验收场景**：运营人员为同一商家选择 2–5 个已有营销周期，分别填写预计单课准备时间和预计成本，再填写总预算与每日可用准备时间。系统用现有课时、讲稿定稿和商品证据状态计算每个方案的成本、负荷、内容准备度和明确缺口，给出当前最可执行方案；如果没有方案满足条件，必须显示“暂不可执行”和待补事项，不能伪造销量或转化预测。
- **接口变化**：新增已认证 `POST /api/merchant/content/plans/compare`。请求只接受方案 ID、运营估算与约束；服务端从可信租户重新读取实际计划/课时/内容/证据。响应返回版本 `marketing-plan-compare-2026.1`、逐方案派生指标、透明分数、阻断项、推荐 ID 和是否可执行。只读计算，无幂等写入；输入非法为 400，跨租户或不存在资源按现有 404 行为处理。
- **数据变化**：无表、文件和迁移。比较结果不持久化；输入的成本与工时是本次运营估算，不进入账本或分析结果。
- **权限**：沿用商家会话与租户来源。商家成员可读取和比较所属计划；不能引用其他租户计划。公开观众接口不暴露比较数据。
- **失败处理**：少于两个方案、重复方案、预算/时间越界或未知计划时拒绝计算。没有已安排课时、没有已审核证据、讲稿未全部独立定稿、超预算或超每日准备能力均作为明确阻断项；无可执行方案时仍返回排序和补齐建议，但 `readyToExecute=false`。
