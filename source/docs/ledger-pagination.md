# 演示账本分页与本地并发核对

账本接口 `GET /api/merchant/rooms/:id/ledger` 每页最多 200 笔，返回 `nextBefore`；有下一页时将该值作为 `before` 参数。按创建时间、记录 ID 同时倒序排序，解决批量写入同一毫秒时分页不稳定的问题。分页位置必须属于该房间，非法位置返回 400；房间租户权限仍先校验。

互动活动页面支持上一页、更早记录、刷新最新。只有最新页自动刷新，历史页保持当前位置；离开页面或切换分页后，旧响应不覆盖新页面。新写入记录需要返回最新页查看，分页不是数据库快照导出。

## 2026-09-11 本地验证

- 完整测试、类型检查、构建、HTTP smoke 通过；增加 426 笔含同时间记录的分页验证、去重、跨房间位置和跨租户拒绝。
- 500 个独立模拟观众，1,000 次观看读取/心跳请求无失败。
- 375 个红包共 10,007 分全部领取；125 个售罄响应符合预期，375 次重复领取返回原记录。
- Agent 进程停止后，直播 API、心跳、剩余活动领取、模拟结算继续运行。
- 全部应用请求 p95 324.47ms，总过程约 8.28 秒；这些是本机单轮观察，不是服务器容量承诺。
- 测试结算等待上限从约 3.5 秒调整到约 11 秒，匹配现有每 2 秒处理最多 100 笔的队列节奏。未提高生产限流或批次上限。
- 本地浏览器检查了分页控件及空状态；有数据分页由接口测试覆盖。

本测试使用临时数据库和回环地址，没有真实视频、微信支付、外部模型或公网服务器压力。仍需真实媒体并发和生产环境容量测试。
