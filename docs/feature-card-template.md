# 功能卡：填写功能名称

在编写业务实现前填写；在功能文档、Issue 或草稿 PR 中选一处维护，PR 引用同一张卡。每项用简短文字或已有设计链接说明，无变化写“无”。纯文档或样式调整可用简短变更说明代替。执行要求见 [仓库硬门禁](../AGENTS.md)。

## 实现前填写

- **所属模块**：主模块；协作模块及其提供的能力。
- **用户验收场景**：角色、前置条件、实际入口、操作和预期可见结果；本阶段范围及留待后续的部分。
- **接口变化**：新增或修改的公开接口、输入输出、错误、版本与兼容方式；跨模块调用的超时和幂等约定。已有契约直接链接。
- **数据变化**：数据所有者、表或文件变化、版本与迁移影响。涉及文件时引用存储设计，说明分类、落点、元数据与来源、权限、配额、引用保护、清理及备份恢复。
- **权限**：可信身份与租户来源、允许的角色及资源范围、拒绝访问和权限撤销后的行为。
- **失败处理**：适用的校验失败、超时、中断、取消、重试、回滚或恢复，以及用户看到的提示；模拟或未配置能力如何标识。

已有规则直接引用：[模块规范](module-development.md)、[存储规范](storage-architecture.md)及相关接口或业务文档。范围改变时先更新卡片，再继续实现受影响部分。

## 随实现补充证据

- **流程结果**：实际完成了什么；保存类操作是否重新读取验证；涉及界面时记录实际操作结果。
- **基础检查**：验证的提交 SHA 或工作区差异、`npm run check` 结果、对应 CI 链接（尚未运行则注明）。
- **专项验证**：按 AGENTS.md 的改动范围填写适用场景、测试位置或命令和结果；已有测试充分覆盖时引用，不适用时说明原因。
- **阶段状态**：待实现 / 实现中 / 待验证 / 本阶段验收通过；未完成项、已知限制，以及模拟与真实环境的验收区别。

有部署时另用[发布验收记录](release-verification-template.md)，不要把本地验证状态当作线上运行状态。
