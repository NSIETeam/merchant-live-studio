# 开播准入

生产环境强制启用；本地可设置 REQUIRE_REVIEWED_LIVE=true 联测。生产环境即使设置 false 也不会关闭。已有权限检查继续生效，准入检查不授予开播权限。

开放直播间和接收新推流时核对：

1. 当前商家有另一账号复核发布、未撤回的经营者公示。
2. 本场绑定的讲稿已独立审核，商品依据、内容检查和授权状态仍有效。
3. 配置推流回调鉴权及 MediaMTX 控制地址，控制服务返回有效实例信息。当前首发强制准入仅支持 MediaMTX；SRS 仍是开发适配，需补断流控制后才能用于该模式。

控制探测使用 MediaMTX 1.21 的 [GET /v3/info](https://github.com/bluenviron/mediamtx/blob/v1.21.0/api/openapi.yaml)。普通 404、错误 JSON、控制连接失败不能算服务可达。回调配置需排除 api 操作，避免控制请求反复触发推流鉴权；见 mediamtx-server.yml.example。Docker 本地默认配置仍是开发用途，要测试强制准入须另行配置鉴权与控制服务，不能只改一个开关就视为具备生产条件。

外部状态读取后，再在本地事务中核对资料并写开播状态和不可改写的准入记录。推流鉴权等待期间如果房间结束或密钥轮换，则拒绝旧请求。重复设置 live 不重复生成记录。结束直播、重置待播不要求准入通过，便于故障处置。

接口：

- GET /api/merchant/rooms/:id/admission：检查项、缺项原因及是否强制。
- GET /api/merchant/rooms/:id/admission-report：重新执行同一检查并下载带生成时间、房间摘要、依据版本和限制说明的 JSON；不包含密钥、正文、观众或资金记录，不能作为行政许可结论。
- GET /api/merchant/rooms/:id/compliance-review-package：下载当前已发布的平台与商家公示、留存政策、商品事实及出处、独立审核定稿正文和技术准入结果；正文附 SHA-256，其他租户和观众不可读取。详见[逐直播间提审材料包](compliance-review-package.md)。
- PATCH /api/merchant/rooms/:id：原有状态接口，强制模式缺项返回 409。
- GET /api/merchant/rooms/:id/admissions：开播记录，含公示版本、课程与稿件版本、操作账号、时间；默认 50 条，使用 nextBefore 继续。

迁移 v14 新增 live_admissions 表。界面检查仅供准备参考，服务端每次操作重新判断，不能通过改页面绕过。讲稿采用 Agent 导入稿时沿用授权状态核对策略；手工稿无 Agent 导入来源则不依赖模型服务。

边界：这是技术准入，不是资质审核结论。真实身份核验、许可有效性、现场布景/服装审查、监控人员、录像留存仍需补齐。公示或依据撤回后会拒绝新的开播/推流请求；已经建立的媒体连接尚不由该模块自动终止，需人工停播，后续要补现场处置链路。控制接口可达也不等于证明真实媒体已被阻断。

验证：138 项全套测试、构建和 HTTP 冒烟通过。覆盖缺公示/定稿、控制 404/故障、正常准入与重复请求、依据变化、公示撤回、等待控制响应时结束房间、跨租户访问、不可改写记录。媒体返回值由本地 HTTP 测试服务模拟，不宣称真实推流验收。浏览器验证缺项提示、点击开放被拒绝、房间保持待开播。尚未部署。
