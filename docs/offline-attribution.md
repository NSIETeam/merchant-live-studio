# 门店来源与线下复盘（本地开发，尚未统一部署）

## 使用流程

管理员在数据复盘中创建门店，为当前直播间创建员工或社群来源链接。观众通过该链接实际观看时建立归属；分析员可以查看台账，只有管理员可以创建来源、导入或修订。

线下台账采用 JSON 数组，每批 1–100 条，页面限制 24KB。先检查预览，再确认保存；任意冲突使整批不写入。模板字段：

```json
[
  {
    "kind": "order",
    "externalId": "门店真实业务编号",
    "occurredAt": "2026-09-11T10:00:00+08:00",
    "amountYuan": "19.99",
    "sourceCode": "来源链接中 source 的值；没有则留空",
    "customerRef": "可选内部匿名编号",
    "note": "台账备注"
  }
]
```

kind 为 visit（到店，金额必须 0）、order（订单净额）或 cost（已登记成本）。金额必须是字符串，最多两位小数，内部用整数分。禁止把顾客姓名、手机号当作必填项。

## 统计定义

- 每个浏览器、每个直播间保留第一个有效来源。换浏览器可能重复计数，共用浏览器可能少计，不能当作实名人数。
- 观看时长仅计建立来源之后增加的有效观看秒数；停用来源阻止新增归属，已有归属和历史观看不删除。
- 到店为登记次数，订单为业务编号数量，均只汇总最新、未作废版本。不会自动计算人级转化率。
- 订单、成本和到店来自商家登记，系统尚未核验收银流水。净额允许通过修订扣除退款；不把毛成交额当净收入。
- 缺来源、未知来源、门店不符或事件不在来源有效期的记录可保存，但单列为未关联。关联只表示业务人员提供的来源对应，不证明直播的因果增量。
- 当前为累计汇总，不是指定日期报表；导出按钮明确只导出已加载记录，可继续加载下一页。并发修订期间分页不是冻结快照，严谨结算应暂停录入后刷新。

## 审计与接口

接口前缀 `/api/merchant/attribution`：stores、sources、sources/:code/disable、imports/preview、imports、records、records/:id/history、summary。

导入需 `storeId`、`sourceName`、`rows`；确认提交再加 `idempotencyKey` 和 `acknowledged: true`。相同请求编号重试返回同一回执，内容变动返回冲突。相同业务编号和相同内容跳过；修订需 `previousVersion` 为当前版本，并填写 note 原因。作废设 `voided: true`，原始记录始终保留。批次、记录、归属均受数据库不可修改/删除约束保护。

数据库迁移 v9 在统一交付时随应用执行；当前线上仍保持原版本。来源链接不含推流密钥或商家凭据。查看/导出受商家和角色权限控制。

## 验收边界

自动测试覆盖整数金额、重复重试、批次原子性、修订/作废、历史不可变、跨商家隔离、角色隔离和来源首触计时。本地浏览器已用合成资料走通新增门店、单条订单表单、预览、确认保存与未关联金额展示。仍需来源分享、修订和导出的完整浏览器验收、门店真实台账核对及与微信实名身份的正式映射；这些不能由局部操作或合成数据证明。
