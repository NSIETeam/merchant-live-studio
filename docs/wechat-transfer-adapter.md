# 功能卡：微信商家转账 APIv3 适配器

## 实现前填写

- **所属模块**：`payments` 模块提供微信商家转账的纯传输与密码学适配器；身份、领取资格和账本仍由各自模块负责。适配器不访问业务数据库，也不从浏览器接收 OpenID。
- **用户验收场景**：后续取得已获批微信支付商户配置后，支付 worker 可使用服务器已核验的收款身份发起转账、按原商户单号查询未知结果，并验签解密终态通知。配置缺失时仍明确不可用，不能把接口代码存在显示为到账。
- **接口变化**：保留 `PaymentProvider` 的发起、查询、通知验签三项契约；`WeChatPaymentProvider` 增加显式配置和可替换 HTTP 传输。当前商家与观众 HTTP 接口不启用真实资金。
- **数据变化**：Live schema 本地候选由 v24 升至 v26。`payments` 新增 `payment_transfers`、不可改写的 `payment_transfer_events` 和 `payment_notification_receipts`；`identity` 新增不可改写的 `wechat_recipient_authorization_events`。OpenID 仅在 OAuth 后短时保存在进程内，观众明确授权后以 AES-256-GCM 密文保存，并另存按商家隔离的 keyed digest；支付模块只保存 digest，不保存 OpenID 明文。
- **权限**：调用者必须提供与配置租户相同的内部商家 ID、服务端核验的 OpenID、唯一且符合微信规则的商户单号和整数分金额。适配器固定使用服务器配置的商户号、场景、备注、报备字段、通知地址和密钥，不接受观众覆盖。
- **失败处理**：请求和响应均有 8 秒/64 KiB 边界；所有微信应答及通知必须用配置序列号对应公钥验签，签名探测流量被拒绝。通知仅接受商家转账终态，使用 APIv3 密钥进行 AES-256-GCM 解密并核对商户号。创建请求失败或结果未知时不换单重付，应查询原单。

## 随实现补充证据

- **协议依据**：发起端点、参数、单号与状态按微信支付当前[发起转账](https://pay.wechatpay.cn/doc/v3/merchant/4012716434)说明；通知验签、终态、幂等和 AES-256-GCM 解密按[商家转账回调](https://pay.wechatpay.cn/doc/v3/merchant/4012712115)说明；请求与应答均执行 [APIv3 签名验签](https://pay.wechatpay.cn/doc/v3/merchant/4012365342)。
- **专项验证**：使用两组本地临时 RSA 密钥和 AES-256-GCM 合成通知验证真实密码学路径，覆盖请求规范串与签名、固定参数、应答签名、原单查询、终态解密、商户匹配、坏签名、错单号、非终态和缺失配置。状态存储专项覆盖一领取一单、崩溃后查原单状态、单号/收款人/金额不可变、终态不可回退、通知幂等与同 ID 异文拒绝；身份保险库专项覆盖短时暂存、明确授权、租户隔离、密文防调包、撤回和数据库无 OpenID 明文。
- **阶段状态**：传输、状态存储、收款身份保险库和可恢复支付 worker 已完成并保持默认关闭，尚未接到观众授权界面、OAuth 回调和线上任务调度。真正启用还需要确定多商户资金模式、配置商户证书与平台公钥、完成对账和商户产品/场景审批，并进行微信小额实测。
- **完整验证**：`npm run check` 已通过 220 项业务测试、类型检查、生产构建和 HTTP 冒烟测试。
