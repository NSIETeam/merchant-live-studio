# 功能卡：观众流量过载保护与容量基线

## 实现前填写

- **所属模块**：公共运行能力 `platform/operations` 为主；`identity`、`live` 和 `analytics` 的业务规则保持不变。流媒体继续由 MediaMTX/SRS 承载，应用容量结果不代表视频 CDN 容量。
- **用户验收场景**：直播突然涌入观众时，平台为商家开停播、审核、流媒体回调和健康检查保留处理空间；超过应用并发上限的观众请求立即收到可重试的繁忙提示，不在服务内无限排队。运维人员可在隔离环境运行分阶段容量探针，得到各阶段请求量、成功率、状态码和 p50/p95/p99，并在错误率或延迟越线时自动停止。远程目标必须显式授权，默认不能误压线上服务。
- **接口变化**：`GET /api/health` 兼容新增 `capacity` 快照；过载的观众流量返回 HTTP 503、`Retry-After: 1` 和稳定错误文案。新增环境变量 `REQUEST_CONCURRENCY_MAX`、`AUDIENCE_CONCURRENCY_MAX`；后者必须小于总上限。既有业务成功响应不变。
- **数据变化**：无数据库、表、文件或迁移变化。并发计数和拒绝计数仅在进程内存中保存，重启归零；容量探针只输出本次测量 JSON。
- **权限**：过载保护不读取或改变业务身份。商家、流媒体回调、支付通知和健康检查使用预留容量；观众认证、公开房间读取及观众接口共用观众容量。远程探针仅允许 HTTP(S)，必须使用 `--allow-remote=<目标主机>` 精确匹配目标，不接收登录密钥。
- **失败处理**：计数在请求完成、异常或客户端中断时均释放；总上限耗尽时所有新请求快速失败，观众上限耗尽时只拒绝观众流量。探针设置总时限、单请求超时、最大阶段和停止阈值；目标不可用、响应不符合预期或阈值越线时非零退出，不给出容量通过结论。

依据：[模块开发规范](module-development.md)、[流媒体边界](streaming.md)、[现有并发验证](acceptance.md#小规模并发与故障隔离)。

## 随实现补充证据

- **流程结果**：API 已在身份和业务路由之前执行并发门禁，健康接口公开限额、当前值、峰值和累计拒绝量；观众达到独立上限时返回 503，同时剩余槽位仍可处理商家控制请求。只读探针完成健康与房间预检后按阶段升压，输出吞吐、p50/p95/p99、状态分布和停止原因。
- **基础检查**：`npm run check` 通过，含架构与数据归属检查、190 项业务测试、类型检查、生产构建和 HTTP 冒烟；高等级依赖审计为 0 个漏洞，部署脚本 9 项测试通过。
- **专项验证**：5 项专项测试通过，覆盖观众饱和、控制余量、请求结束释放、错误配置、健康目标、429 分类和远端明确授权。探针支持根路径及 `/studio/` 一类显式子路径，不接受含遍历或查询的路径。独立本地进程完成 10/25/50/100 并发、每阶段 200 次公开房间读取，800/800 返回 200，各阶段 p95 最高 21.46 ms。另有 500 个模拟观众完成 1000 次观看业务请求，0 个工作负载失败；375 个红包共 10007 分全部守恒，Agent 停止后直播链路继续运行，当次全请求 p95 为 173.58 ms。
- **阶段状态**：本地候选已通过本阶段验收，留待后续批量发布。上述数字来自同机回环与合成资料，只证明门禁行为和工具可复现；不等于万人容量、原服务器容量、跨网 CDN、真实播放或多实例数据库验收。
