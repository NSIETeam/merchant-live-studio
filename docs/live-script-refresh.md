# 直播讲稿刷新与失效展示

讲稿请求改为串行轮询：一次完成后等待 5 秒再请求，8 秒未完成则超时。超时或读取失败后暂停展示讲稿，下一次成功核对后恢复。此机制仍存在轮询窗口，不代表审核撤回零延迟到达，也不会替代服务器开播准入与现场断流。

请求超时、重新刷新、切换直播间或离开页面时取消旧请求；即使旧请求忽略取消后才返回，代次校验也会丢弃结果。页面进入后台时暂停轮询，回到前台先暂停展示并立即重新核对。

`tests/poll-resource.test.ts` 使用可控时钟和延迟响应，验证：慢请求不叠加；超时后重试；较旧的通过结果不能覆盖较新的撤回结果；后台暂停不继续请求；恢复重新读取；停止后不交付结果。全套构建与检查另外执行。浏览器可见效果仍需解锁后验收。
