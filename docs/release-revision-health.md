# 功能卡：线上运行版本核对

- **所属模块**：`platform/infrastructure` 读取发布包内固定 `REVISION` 文件，`platform/operations` 在健康接口公开该非敏感提交号；业务模块和数据库不参与。
- **用户验收场景**：自动部署完成后，运维人员读取 `/api/health` 即可把正在运行的完整 Git SHA 与工作流目标 SHA 对照。开发环境没有发布文件时明确返回 null；发布文件无效时服务拒绝以错误版本标识启动。
- **接口变化**：`GET /api/health` 兼容新增 `revision: string | null`。只接受 40 位小写或大写十六进制提交号，响应统一为小写。
- **数据变化与权限**：不新增数据库；只读取进程工作目录下构建包已有的 `REVISION` 文件，最多接受一行固定格式。提交号为公开仓库标识，不包含凭据。
- **失败处理**：文件不存在按本地非发布环境处理；存在但不可读或内容格式错误时启动失败，防止健康接口报告未经验证的版本。自动部署仍负责把目标 `GITHUB_SHA` 写入发布包。

## 随实现补充证据

- **流程结果**：配置启动时读取并规范化发布包 `REVISION`，健康接口兼容返回 `revision`。当前线上版本尚未包含此读取逻辑，因此仍按既有工作流日志和功能响应核对；下一次部署后应要求健康值与目标 SHA 完全一致。
- **专项验证**：独立临时目录覆盖文件缺失、40 位大写 SHA 规范化为小写和短值拒绝；部署脚本既有测试继续覆盖归档白名单、包内 revision 与部署命令一致性。
- **基础检查**：完整 `npm run check` 通过 207 项业务测试、架构和数据归属门禁、类型检查、生产构建及 HTTP 冒烟；高等级依赖审计为 0 个漏洞，部署脚本 9 项测试通过。
- **阶段状态**：本地候选完成，只有下一次集中部署后从公开健康接口读到目标 SHA，才算完成线上版本直接核对。
