# 功能卡：逐直播间提审材料包

## 实现前填写

- **所属模块**：`live` 负责按直播间生成即时导出；`review` 通过公开端口提供已发布经营者公示；`content` / `knowledge` 通过既有有效绑定提供定稿与商品证据快照；平台主体和留存政策来自服务器可信配置。模块不互相读取私有表。
- **用户验收场景**：商家在“开播准备检查”下载一份 JSON 提审材料包。材料包包含生成时点、直播间、平台主体、留存政策、当前已发布经营者公示、已绑定商品证据快照、独立审核定稿和技术准入结果；缺少资料时保留明确的 `null` 与缺项，不拼造内容。审核人员可据此核对版本和原件位置，不能把导出成功当作资质获批。
- **接口变化**：新增商家接口 `GET /api/merchant/rooms/:id/compliance-review-package`，返回 UTF-8 JSON 附件并禁止缓存。只接受当前登录商家拥有的房间，不增加公开或观众入口。
- **数据变化**：无数据库迁移、无业务写入。导出即时读取当前版本并复制到下载响应，不在服务器另存副本。内容包括商品事实与定稿正文，属于受控审核资料；不包含推流密钥、登录密钥、模型密钥、观众身份、转写记录、资金账本或内部数据库字段。
- **权限**：沿用商家会话和房间租户校验，仅 owner、editor 和 reviewer 可下载，presenter 与 analyst 不可读取整包审核资料。经营者公示只能取当前有效发布版本；内容只能取当前房间有效的独立审核绑定。其他租户得到 404。浏览器公开直播页不能读取材料包。
- **失败处理**：媒体控制不可达时仍生成材料包并在准入检查中如实标为失败；缺少平台、留存、公示或定稿时相应区块为 `null` 并列出缺项。同步授权检查失败或导出读取异常返回失败响应，不生成看似完整的附件。

## 随实现补充证据

- **流程结果**：工作台新增“下载提审材料包”。服务端先同步当前授权并重新执行媒体与六项准入检查，再即时导出版本化 JSON；平台、留存、有效商家公示、商品事实与出处、独立审核正文均通过明确字段提供，缺项保留为 `null` 和结构化清单。响应使用 `Cache-Control: no-store`，文件名限定于当前房间，并在 `X-Content-SHA256` 返回实际正文摘要。
- **专项验证**：扩展准入流程测试，先验证缺少公示和定稿时导出不冒充完整，再建立合成平台配置、商家公示、商品事实、出处、两段讲稿及独立审核，验证完整材料重新读取一致。测试同时覆盖 reviewer 可读取、presenter 被拒绝、其他租户 404、正文摘要匹配以及会话、推流和成员密钥不进入附件。
- **界面验证**：本地真实浏览器在 1280×900 和 390×844 打开开播准备区，均找到提审材料包入口并通过商家会话取得 HTTP 200 JSON 附件；未配置环境返回 5 项缺失、内容为 `null` 和 4 条限制。两种视口横向溢出为 0，未发现绿色界面。
- **发布前验证**：完整 `npm run check` 通过，包括架构与数据归属门禁、207 项业务测试、类型检查、生产构建和 HTTP 冒烟；生产依赖审计为 0 个已知漏洞，部署脚本 9 项测试及语音中继构建入口语法检查通过。
- **阶段状态**：本地业务与界面流程完成；真实主体、许可、商品原件及审核机构验收仍需外部材料，当前附件不构成获批结论。
