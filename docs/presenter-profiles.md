# 主播档案与表达方案（本地开发，未统一部署）

在“表达与提示词 → 提示词与风格调试 → 真人主播档案”绑定主播展示名、工作角色、表达特点、节奏与授权依据。留空表示通用表达；建议保留通用方案，为每位获授权主播建立独立品牌方案。

档案保存在 Agent 自己的提示词版本中，和样例共同版本化。新建、保存版本、样例导入均保留档案；短句试演及长稿任务冻结各自使用的快照，修改当前资料不会改写历史任务。无需新增 Live 数据库表。

前端在资料不全或未确认授权时禁用保存；Live 入口与 Agent 服务共用字段校验，缺授权确认的请求即使绕过页面也会被拒绝。编辑档案字段会清除本地确认状态，需重新核对。

## 模型边界

模型仅接收档案中的 speakingStyle 与 pace；displayName、roleDescription、authorizationReference、authorizationConfirmed 从这两种模型请求的档案字段中剔除。请勿自行将合同、联系方式或身份资料粘贴到会发送给模型的系统提示词、风格目标、样例或表达特点里。

档案用于文字表达，不提供声音克隆、数字人或冒充真人的能力。固定规则要求风格数据不能变成商品证据，不得据此虚构个人经历、专家资格、代言、功效或消费体验。授权确认是商家声明，系统不验证合同真实性。

提示词和动态数据保持不同指令层级；实现参考 [OpenAI 提示词工程说明](https://developers.openai.com/api/docs/guides/prompt-engineering)。这只是输入边界设计，不能证明模型一定遵守风格或所有合规要求；仍需真实模型、多版本评测与人工复审。

## 尚未完成的验收

当前没有档案到期、撤回授权后的全版本停用或已排队任务撤销机制。保存一个不带档案的新版本不会自动使旧版本失效。正式使用真人材料之前仍需补全授权状态管理，并取得真实样例。

自动测试覆盖缺授权拒绝、Live 到 Agent 的字段传递、多版本保存、任务快照、样例导入保留以及两条模型请求的字段剔除。真实模型尚未配置，本地规则输出不能视为主播风格训练效果。

本地浏览器已验证：未确认授权时保存按钮禁用；确认后通过 Live 入口成功建立独立主播方案，并回显档案与 V1，原通用方案保留。首次联测发现的 Live 校验缺字段已修复，并新增跨服务回归测试。
