# 平台资料与留存政策开播准入功能卡

主模块为 `live`，协作输入来自只读服务器配置 `platform/infrastructure`；不新增数据库表，不允许 Agent 改变准入结果。目标是在正式开播和每次真实推流发布时，同时核对平台运营主体与记录留存政策，避免“页面提示未配置但生产仍可开播”。

`live` 只读取配置已经完成的结构化校验结果。准入增加「平台主体与政策」和「记录留存政策」两项；缺少任一项时 `ready=false`，工作台显示具体补充提示。成功开播的不可改写准入快照记录平台政策生效日期和留存政策生效日期，便于回看本场使用的配置版本；不保存完整地址、联系方式或协议正文。

生产环境强制启用既有审核准入，因此两项成为生产硬门槛。本地演示默认不执行准入，仍可浏览；如果开发者显式开启审核准入，同样必须提供两项配置，确保测试行为与正式门禁一致。

验收场景：两项缺失时即使商家公示、讲稿和媒体控制均满足也不能开播；补齐后可以通过；准入接口能逐项解释；成功快照保留两个生效日期；推流发布会重新核对当前准入；公开观众接口不暴露完整准入快照或内部配置。

## 本地验收记录（2026-09-11）

专项测试使用隔离数据库确认两项缺失时 `ready=false`，返回各自明确原因；完整准入流程使用合成的平台及留存配置成功开播，并从不可改写历史重新读取两个政策生效日期。既有公示过期、商品依据变化、撤回、媒体控制异常和推流二次核对场景继续通过。

构建后的工作台在审核准入开启且两项配置缺失的隔离实例中实际打开，展开「开播准备检查」可见两个独立的“待补齐”项目。390 × 844 视口横向溢出为 0，两个原因均可见，页面未发现绿色状态色。测试服务、临时数据库和浏览器视口在验收后清理。
