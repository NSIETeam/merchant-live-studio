- **线上只读基线**：部署基线上的公开房间 JSON 已完成 10、25、50 并发三档各 100 次短时远程读取，300 次均为 HTTP 200、0 错误；最高阶段 p95 848.32 ms。该结果不包含媒体、写请求或真实观众业务，详见[容量保护与基线](capacity-guard.md)。
- **迁移与数据**：Live schema 从 v23 升至 v24，新增每个房间一行的 `speech_relay_status` 运行状态，不保存音频、转写正文、模型地址、密钥或原始错误。微信 access token 与 JSAPI ticket 仅在进程内短时缓存；发布报告为即时生成的只读附件；语音中继只在进程专属临时目录保存有界 WAV，投递后删除并在退出时清理。发布包的 `REVISION` 由现有工作流写入完整提交 SHA，应用只读取固定文件并拒绝短 SHA 或畸形内容。
- **配置条件**：`WECHAT_JS_SDK_ENABLED` 默认关闭，只有完整公众号 OAuth 配置同时存在时才允许启动。未配置时渠道接口和观众页如实显示不可用。语音中继只有在运维人员安装独立私有环境文件并合并 MediaMTX hook 片段后才会运行；正式启用前仍需已审核公众号、备案 HTTPS 域名、JS 接口安全域名、微信客户端验证，以及实际 ASR 模型、FFmpeg 路径和中文效果核对。
- **备份与回滚**：沿用现有 main 自动部署的直播空闲保护、双数据库快照、发布目录切换和旧版本回滚。v24 只增加独立运行状态表，旧服务不会读取该表；回滚应用版本时保留数据库和该表，不执行破坏性降级。实际备份位置、提交 SHA 和产物核对待合并部署后填写。
