# 初始验证与下一步

验证日期：2026-09-11。Node.js 24.20.0 / macOS arm64。

## 已完成验证

- `npm run check`：14 项 API/服务测试、TypeScript 检查、Vite/服务端构建，以及构建后真实 HTTP 服务测试。
- 测试包含跨租户拒绝、公开接口秘密隔离、Origin/JSON/伪造 Cookie/大请求拒绝、房间持久化、观看资格、30 个并发请求争抢 20 个红包、金额守恒、重复领取、outbox 重跑、故障回滚、到期余量退回、倒计时、事实依据与风险、推流鉴权、代理后多会话限流、统计与真实支付禁用。
- HTTP 测试在独立内存数据库中启动构建后的服务，验证首页、观众路由、JS 资源、同源登录、创建/开放直播间、演示活动、观众心跳、领取、自动 worker、统计及源码不可公开读取。无真实出款或外部视频依赖。
- `npm audit --omit=dev --audit-level=high`：本次检查报告 0 个已知漏洞；该结果不构成长期安全保证。
- 源码与文档经过格式化。首屏 JS gzip 约 83 KB，HLS 播放器 gzip 约 185 KB，点击连接后按需加载。构建对 HLS 独立包发出体积提示，不影响构建成功。
- 已通过 GitHub API 全量核对源协作者，邀请结果见 [协作者记录](collaboration.md)。

API 测试中的 `forced-outbox-failure` 是主动注入的回滚用例，日志不代表测试失败。HTTP 测试默认使用 18791 端口，可用 `SMOKE_PORT` 修改。

## 尚未验证 / 尚未接入

- 当前环境没有 Docker、OBS 或 FFmpeg，因此没有运行容器，也没有验证真实 RTMP→HLS 视频、音频、移动端或微信内播放；不能把生成了播放地址视为视频链路验收通过。
- 没有执行浏览器点击/视觉/可访问性端到端测试，界面通过静态审查和编译检查；真实交互与多设备回归仍需补充。
- 未接入微信 OAuth、商户产品准入、用户收款授权、真实转账、验签回调及对账。演示领取不是提现能力。
- 提词为本地规则与审核事实拼接，尚未接入远程 LLM、实时 ASR 或行业合规引擎。它不保证完整语义正确或广告合规。
- 尚未做负载测试、恶意流量实测或商业上线审核。没有网站公网部署，本交付为私有 GitHub 源码和本地预览。

## 建议后续顺序

1. 在有 Docker/OBS 的环境完成单引擎联调、发布鉴权、错误密钥拒绝、重连/断流、手机与微信 HTTPS 播放，并补流状态同步/强制停流。
2. 接入正式商家身份、微信观众身份、会话撤销和防刷，确定租户级商品事实审核与证据存储。
3. 为 LLM/ASR provider 接入授权与隐私配置，验证基于事实的生成、完整语义风险和模型不可用时的回退。
4. 取得适用微信支付产品及场景权限后，独立实现支付订单、用户确认、回调验签、幂等状态机、对账与人工异常处理，再进行授权的小额验收。
5. 用明确的并发目标压测，决定是否迁移 PostgreSQL、Redis 原子领取和独立队列；接入 CDN、监控、审计与备份恢复。
