# 平台存储规范与开发门禁

本规范承接[模块开发规范](module-development.md)，约束后续涉及数据、附件、生成结果、直播媒体和清理备份的开发。核心规则是：**业务数据按模块拥有，文件按用途和生命周期分层，所有文件通过受控资产引用使用。** 文件扩展名只用于格式处理，不能决定业务归属、审核状态或访问权限。

## 当前实现与目标边界

当前业务服务使用 `data/studio.sqlite`，Agent 使用 `data/agent.sqlite`；两者已分离，均启用 SQLite WAL。Docker Compose 中对应独立的 `studio-data`、`agent-data` 卷。现有导入主要接收文本内容，尚未实现本规范中的统一附件服务、对象存储、录制归档和自动清理。

本次固化开发规则，保留现有数据库路径、卷和业务数据。以下新目录、资产字段、接口及期限是后续实现的约束，不代表已经启用；不得仅添加环境变量、空文件夹或文档就宣称上传、备份或录制已完成。

## 分类与唯一所有者

| 数据或文件                                           | 所有者                            | 存储方式与规则                                                                                                         |
| ---------------------------------------------------- | --------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 商品、计划、客户、场次、审核、积分、资金等结构化记录 | 对应业务模块                      | 业务数据库的所属表；起步可共用一个业务库，禁止跨模块直接读写表                                                         |
| 提示词、风格、任务状态、短文本输入输出、评测         | agent                             | Agent 数据库；发布版本与任务快照不可变，文件或日志不充当第二份权威状态                                                 |
| 商品说明、资质、授权书、规则原文等 Word/PDF/图片     | knowledge                         | 私有原件 `original`；核实后的事实版本入知识业务表，原件不被提取结果覆盖                                                |
| 旧讲稿、授权主播录音与风格样例                       | content / agent                   | 旧讲稿及可复用媒体归 content；专门导入的训练样例、样例授权记录归 agent；knowledge 只管理商品和规则证据，不收纳所有文件 |
| OCR 文本、转录、切片、缩略图及向量索引               | 来源所属模块                      | 可引用的转录、切片等保存为 `derived` 资产，记录来源版本及处理参数；检索索引单独保存且可重建，不作为证据原文            |
| AI 生成候选稿、候选图、候选音视频                    | agent                             | 小文本与结构化结果存 Agent 数据库；大附件存私有 `candidate` 对象，采纳前不成为正式内容                                 |
| 正式编辑的讲稿、海报、图片、音频、视频和课件         | content                           | 讲稿正文及版本关系入库，二进制原件和派生文件存私有对象；修改生成新版本，不覆盖旧版本                                   |
| 审核决定、发布包与撤回记录                           | review                            | 数据库中保存不可变决定及版本清单，引用内容资产；“发布”不是将文件移入公开目录                                           |
| 直播原始录像及场次录制清单                           | live                              | 独立的持久化 `recording` 区，以独立场次 ID 关联；录制文件分段完成并校验后才成为可用资产                                |
| 直播 HLS 清单、分片及转码缓存                        | live，流媒体引擎执行              | 独立的媒体缓存区，随播放窗口滚动回收；不是录像备份，也不进入业务数据库                                                 |
| 客户服务附件、订单凭据、礼品或支付凭证               | customers / engagement / payments | 归产生业务事实的模块；私有对象与本模块记录关联，不混入知识库或默认提供给 Agent                                         |
| 下载导出、统计报表                                   | 发起业务模块                      | 可重建的下载副本存 `export` 并设置到期时间；需要留存的业务报表另登记为持久资产                                         |
| 上传分片、解压、转码和生成中间产物                   | 任务所属模块                      | 隔离区及 `tmp`，记录上传/任务 ID、租约与到期策略；不能当作正式素材地址                                                 |
| 运行日志、访问审计、备份                             | operations 协调，各模块提供接口   | 分别进入日志、审计记录和备份系统；资金账本仍归 payments，业务审核记录仍归 review                                       |

同一资产登记时必须有一个确定的 `ownerModule`。表中的多个模块表示不同用途的归属选择，不表示共同写同一记录。跨模块使用通过授权引用；跨模块采纳生成独立的接收方资产，具体流程见下文。

短文本、JSON、提示词和讲稿可以保存在数据库中。禁止把大型音视频、图片或整份上传文件以 Base64 塞入业务 JSON；较大的模型原始输出应作为受控附件，任务表保存摘要和引用。每个接口明确体积上限，不能仅用文件后缀判断存储方式。

## 目录、对象键与环境隔离

本地开发约定如下，新增运行目录统一放在 `var/`，不进入 Git 或镜像构建上下文：

```text
data/
  studio.sqlite                  现有业务库，路径保持不变
  agent.sqlite                   现有 Agent 库，路径保持不变
var/
  objects/private/tenants/<tenantId>/<ownerModule>/<class>/<assetId>/<version>/<rendition>
  quarantine/<ownerModule>/<uploadId>/   待验证上传，仅处理进程可读
  tmp/<ownerModule>/<jobId>/             有租约的任务中间文件
  cache/media/<sessionId>/               引擎管理的播放缓存
  cache/search/<tenantId>/<indexVersion>/ 可重建索引，权限仍需校验
  logs/<service>/                        脱敏运行日志
  backup-staging/<backupId>/             备份暂存，不等于完成异地备份
```

`class` 使用 `original`、`derived`、`candidate`、`recording`、`export`。数据库保存语义用途，例如商品资质、主播样例、客户凭证；不要不断新增顶层目录来表示 UI 菜单或文件后缀。`rendition` 使用服务端生成的固定名称和已校验扩展名，例如 `source.docx`、`thumbnail.webp`、`transcript.json`。

生产部署使用显式配置的绝对路径、持久卷或对象存储。现有业务库、Agent 库及对应服务权限保持分离；新文件根目录需独立配置和挂载，不能依赖容器可写层。开发、测试、生产使用不同根目录或存储空间和凭据，生产备份单独授权；测试不使用生产数据目录。

上述对象键是逻辑布局，不要求为十个模块建立十个存储服务。起步实现本地文件适配器，后续对象存储适配器沿用同一资产契约；业务记录和前端只使用资产 ID 与版本，不能绑定本机绝对路径、桶名或永久下载 URL。

租户、模块、资产和任务标识由可信服务端上下文生成或校验；原始文件名只作为展示元数据。禁止将手机号、客户姓名、证件号、访问令牌写入路径；禁止客户端提供目标绝对路径或任意对象键。路径解析必须限制在配置根目录内，阻止 `..`、绝对路径、符号链接及 Windows 路径变体逃逸。随机 ID 和目录前缀不能替代鉴权。

`public/`、`src/`、`dist/` 只放源码和随版本发布的应用资源。任何用户上传、客户凭证、AI 工作文件、录像和数据库都不能通过静态目录直接暴露。经人工确认可公开的应用品牌图标可继续位于 `public/brand/`。

## 资产记录、版本与引用

每个持久文件版本至少登记以下信息，由所属模块的 `persistence/` 管理：

| 字段组           | 必须记录的内容                                                               |
| ---------------- | ---------------------------------------------------------------------------- |
| 身份与所有权     | `assetId`、`version`、`tenantId`、`ownerModule`、业务记录 ID、用途及 `class` |
| 对象定位与完整性 | 内部存储定位符、字节数、经验证的 MIME、SHA-256；文件名仅展示                 |
| 来源             | 上传者、来源说明、授权记录引用、原资产与版本、导入或生成任务 ID              |
| 派生追溯         | 处理器及版本、处理参数；AI 产物另记录模型、提示词、风格和证据快照版本        |
| 状态             | 存储状态、创建/完成时间、失败原因码；审核与发布状态由 review 独立管理        |
| 权限与保留       | 访问策略引用、到期策略、保留标记、删除申请与执行记录                         |
| 引用             | 使用方模块、业务对象、资产版本及引用状态；由资产所有者登记和保护             |

存储状态建议为 `pending → ready → delete_pending → deleted`，验证失败为 `rejected`。`ready` 只表示字节已验证并可按权限读取，不能表示批准发布。修改文件、讲稿、提示词或来源快照产生新版本；版本中途失败不能覆盖最后一个可用版本。

模块可共享元数据契约，不共用一个可任意写入的全局业务表。每个模块只维护自己的资产记录；统一文件基础能力处理字节、校验和受限读写，不决定商品事实、发布资格或资金状态。

引用必须固定到版本。跨模块通过所有者的接口建立持久引用后，才能提交使用方业务状态；调用使用幂等键，超时和未知结果先查询再重试。使用方失败后通过补偿释放引用。删除前由所有者原子检查引用并转入 `delete_pending`，此后拒绝新引用；释放失败或引用状态不明时保留文件，不能依靠最终一致的计数直接删除。

允许同租户、权限和保留策略兼容的内部去重，但不能向用户透露其他租户是否拥有相同文件。初期不实现跨模块共享物理对象的去重；以后引入时，必须先实现多方引用及删除保护，不能仅凭哈希相同共用可删除对象。

## 模块接口与文件处理流程

业务资产接口位于所属模块的 `public.ts`，通用存储适配器位于 `src/platform/infrastructure/`，由装配层注入。数据库访问继续留在业务模块 `persistence/`。禁止业务代码自行拼接磁盘路径、调用存储厂商 SDK 或绕过资产登记落盘；现有数据库初始化与流媒体引擎自身的文件操作按各自运行边界管理。

先实现以下能力契约，再开发上传界面：

| 能力          | 输入与结果                                               | 边界                                                         |
| ------------- | -------------------------------------------------------- | ------------------------------------------------------------ |
| 创建上传      | 业务用途、预期类型/大小、幂等键 → 上传 ID 和受限上传许可 | 服务端确定租户和所属模块，预留配额，限定目标、大小和有效期   |
| 完成上传      | 上传 ID → 已验证资产 ID/版本或状态                       | 复核授权、实际字节与校验结果；重复完成返回同一结果           |
| 读取或下载    | 资产 ID/版本、用途 → 流或短期访问许可                    | 校验租户、资源权限、文件状态及需要的发布资格；不返回存储密钥 |
| 建立/释放引用 | 来源模块、业务对象、资产版本、幂等键 → 引用结果          | 由所有者校验使用资格，限制跨模块权限，保护删除并发           |
| 采纳候选结果  | 源任务/候选版本、目标业务对象、幂等键 → 接收方草稿版本   | 接收模块授权，固定来源，独立保存；采纳不等于发布             |
| 请求删除      | 资产版本、原因、幂等键 → 受理/阻止/已删除                | 所有者检查引用、保留策略与操作者资格，异步删除可恢复、可审计 |

接口明确无权限、不存在、格式不支持、超限、版本冲突、文件未就绪、引用阻止删除和存储暂不可用等错误；无权限响应不能泄露其他租户的文件存在性。读取可恢复重试，创建、完成、采纳和删除必须幂等。许可不能因用户提交的租户 ID、owner 或路径扩大范围。

上传先进入隔离区，验证允许的格式、真实内容、体积及校验和，再进行受限解析和必要的恶意文件检测。仅检查 `Content-Type` 或后缀不足以放行；Office/PDF 不执行宏、脚本或外部链接，解压和解析限制总大小、页数、时长及资源消耗。缩略图、转录和转换文件另建派生版本，原件保持不变。上传实现参考 [OWASP 文件上传指南](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)。

文件写入与数据库事务不是一个原子事务。按“登记 pending → 隔离区写入和验证 → 完成不可变对象 → 事务登记 ready → 派生任务”的顺序实现；禁止数据库已显示成功但文件还在上传。各阶段记录幂等状态，进程崩溃后可查询和恢复；孤立对象经过宽限期与所有者核对后处理。消费者只读取 ready 版本。

Agent 采纳流程：先申请保护源候选的引用，再由 content 创建自己的草稿和不可变文件副本，校验完成并固定来源后提交采纳结果，最后释放临时源引用。跨服务通过授权下载或受限复制完成，不能挂载并遍历对方存储根目录。源候选过期不得删除已采纳素材；采纳重试不得重复创建草稿。

例如，纳豆资质 PDF 由 knowledge 保存原件及核实版本；Agent 获得授权的证据快照，生成候选讲稿与配图；content 采纳并保存草稿版本；review 批准确定版本并形成发布清单；live 使用清单并保存本场录像；剪辑成门店传播视频时，由 content 通过授权复制登记新资产，保留录像场次和时间段引用，重新经过所需审核。

## 访问、发布和录制

默认私有；商家、门店员工、消费者和服务账号分别按用途授权。Agent 只获得任务必要资料，不拥有客户/支付文件的通用读取权限。给模型提供文件前按任务范围授权，资料内容是数据，不能变成新的系统指令。

发布包固定资产、内容、证据及审核版本，播放或下载入口校验发布状态。通过受控网关或短时有效访问许可交付；授权 URL 不进入永久业务字段或普通日志。需要即时撤回的内容经可撤销的鉴权入口读取；采用短期链接的场景必须定义其最长残留访问窗口及缓存失效方式，不能承诺已下载内容可被远程收回。

HLS 由媒体链路传输，资产规范不要求让全部视频字节经过业务 API。媒体鉴权、缓存隔离和发布状态检查通过入口及令牌协议衔接；每个独立场次使用独立命名空间，禁止多个场次复用录像文件名。录制分段登记开始/结束时间、顺序、缺段和完整性，断流或异常结束如实标记。缓存清理不得触及录像。

后台转码、导出、Agent 工作区和录像分别设置配额、并发和磁盘水位。优先拒绝新上传或暂停后台任务，保护正在播出的资源。录制失败必须显式告警并记录；不得因保存失败把场次标为“已完整录制”。具体降级行为及容量阈值必须在接入录制时验收。

## 保留、删除与备份

以下是新功能的初始策略，必须配置到所属模块并验证后才可启用清理；本次没有启动清理任务，也不删除现有文件。

| 类别                                        | 初始策略                                      | 执行前提                                                                   |
| ------------------------------------------- | --------------------------------------------- | -------------------------------------------------------------------------- |
| 未完成上传、已结束任务中间文件              | 租约到期且上传失效/任务终结后，再保留 24 小时 | 任务无恢复用途、无活跃使用者、无持久引用；不能仅按文件修改时间删除         |
| 下载导出副本                                | 生成后 7 天到期                               | 到期先禁止下载，再等活跃下载租约结束回收；持久业务报表不适用此规则         |
| HLS 和转码缓存                              | 按引擎播放窗口、容量与访问租约回收            | 与录像物理隔离，不能删除仍在播放窗口中的必要分片                           |
| 检索索引和可重建缓存                        | 按源版本及权限失效后淘汰                      | 源文件保留；撤回或授权变化时停止检索旧内容，重建不扩大原权限               |
| 原始资料、用户草稿、AI 候选、正式素材、录像 | 默认不因年龄自动删除                          | 由所属模块明确保留策略；正式引用、恢复需求、审计或保留标记未解除时禁止回收 |
| 客户资料、业务凭证、审核、账本与审计记录    | 按数据类别确定访问和保留政策                  | 本规范不设统一法定年限；业务留存和隐私删除要求在相应功能中落实             |
| 运行日志和备份                              | 上线配置保留周期、容量和告警                  | 不允许无限增长；备份周期同时满足约定的恢复目标                             |

删除分为撤销访问、检查并锁定引用、异步清除对象、登记删除结果。原始资料撤回还需使相关检索、任务和发布引用进入复核或失效流程；不能只删除磁盘文件而留下“可使用”的业务状态。删除任务携带精确对象版本，不使用整租户目录通配清理。底层删除失败保留可重试记录；元数据先保留删除标记，防止重试和恢复复活旧资产。

备份覆盖两个数据库、持久对象、版本关系、引用与删除记录；HLS、可重建缓存和过期临时文件不纳入。日志不记录模型密钥、会话令牌、签名下载链接、原始客户资料或完整模型输入；需要留存的任务输入进入受控任务记录。

SQLite 使用可靠的一致性备份方式，例如 Online Backup API 或 `VACUUM INTO`；不得将运行中的 `.sqlite` 文件直接单独复制作为完整备份。相关机制见 [SQLite 官方备份说明](https://sqlite.org/backup.html)。业务库与 Agent 库的备份不是天然的跨库事务快照：备份清单分别记录快照时间、模式版本、事件进度和所有被引用对象的版本与哈希。

在生成数据库快照及复制其引用对象期间，暂停相应物理回收或持有备份保留引用，保证清单中的对象仍可获取。对跨库未完成流程按幂等记录恢复；备份验证失败不得标记成功。备份保存在独立故障范围和受限凭据下，`backup-staging/` 只用于中转。

首次生产接入必须明确可容忍的数据损失窗口（RPO）和恢复时长（RTO），并在隔离环境验证：数据库可打开、对象校验一致、引用完整、代表性文件可读、待完成任务不会重复发布或付款。恢复后重放快照以来的撤回和删除记录、重新校验授权，再恢复服务，不能因回滚备份重新公开已撤回资料。备份轮转也需要说明删除数据何时退出备份。

## 开发与交付门禁

涉及存储的功能，开发前必须说明：**所属模块、数据类别、落点、元数据、版本和来源、访问权限、体积配额、失败恢复、保留清理、备份恢复**。没有这些定义，不能以“文件先存下来”为理由交付。

按变更范围验证以下关键场景：跨租户与越权访问被拒绝；路径逃逸和类型伪装被拒绝；上传重试和崩溃不生成伪成功文件；新版本不覆盖已批准内容；候选采纳后源清理不影响正式素材；删除与引用并发安全；撤回后缓存和访问许可按约定失效；播放缓存清理不删除录像；持久数据可按恢复目标还原。

本规范是必须执行的设计、代码审查和运行时验收门禁。现有 `npm run check` 检查模块边界和已实现业务，**尚不能自动证明上述文件存储语义**。新存储功能必须增加对应的有效测试，不得以现有测试全绿代替上传、授权、清理或恢复验收。

落地顺序：先完成资产契约、本地存储适配和原件上传/读取，再接入派生处理及 Agent 候选采纳，然后接入发布媒体和录制归档；自动回收须在引用保护、恢复演练和必要的生产存储配置完成后启用。每一阶段都保留现有数据；未来迁移必须提供校验清单、回滚方案和切换验证。
