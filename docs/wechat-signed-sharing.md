# 功能卡：微信公众号签名分享

## 实现前填写

- **所属模块**：`adapters` 负责微信 access token、JSAPI ticket 与签名协议；`operations` 提供公开但受限的房间签名接口；观众页只消费短时签名并配置微信 JS-SDK。`live`、`agent` 和 `payments` 不读取公众号密钥。
- **用户验收场景**：服务器配置已审核公众号及 JS 接口安全域名后，观众在微信内打开直播间，页面为当前完整 URL 获取短时签名并设置“发送给朋友”和“分享到朋友圈”的标题、描述与链接。普通浏览器继续使用系统分享/复制链接。未配置或微信接口失败时明确显示不可用，视频播放与互动不受影响。
- **接口变化**：`GET /api/channels` 按配置返回微信 `signedSharing`；新增 `GET /api/channels/wechat/share-signature?roomId=...&url=...`。接口只签署当前 `APP_ORIGIN`、当前 `APP_BASE_PATH` 下与 roomId 精确对应的观看页 URL，并返回 AppID、时间戳、随机串、SHA-1 签名和允许的 JS API 列表。新增 `WECHAT_JS_SDK_ENABLED` 开关，必须与完整 OAuth 配置共同启用。
- **数据变化**：不新增数据库或文件。access token 与 JSAPI ticket 只在进程内按上游有效期减去安全余量缓存；AppSecret、access token 和 ticket 不写日志、不返回浏览器。重启后重新获取。
- **权限**：接口无需商家登录，供公开观众页使用，但不能签署站外地址、其他路径、带用户名密码或 fragment 的 URL。后端只访问固定微信 HTTPS 端点；前端仅从固定 `res.wx.qq.com` 加载 JS-SDK。
- **失败处理**：微信非 200、错误码、超时、超限响应或无效字段统一返回 502。并发刷新共享同一个上游请求，失败不缓存。页面保留系统分享和复制链接，且不把“配置完成”表述成渠道审核或真实分享已验收。

## 随实现补充证据

- **流程结果**：动态渠道能力、当前房间 URL 限定签名、固定微信 token/ticket 端点、进程内安全余量缓存、并发请求合并、观众页微信环境判断和 JS-SDK 分享资料配置已完成。签名接口归入观众容量门禁；微信失败不占用商家控制预留容量，也不阻断播放器和互动。
- **基础检查**：`npm run check` 通过架构与数据归属检查、207 项业务测试、类型检查、生产构建和 HTTP 冒烟；高等级依赖审计为 0 个漏洞，部署脚本 9 项测试通过。
- **专项验证**：4 项签名分享测试覆盖显式开关、动态能力、缺失/畸形参数、站外/错房间/fragment/内嵌凭据拒绝、通用上游错误、固定端点、签名重算、秘密不泄露、并发去重和失败不缓存。使用真实 Chrome 检查 1280×900 与 390×844，横向溢出和绿色元素均为 0；普通 Chrome 正确显示“请在微信内打开”且未加载微信 SDK，移动端滚动后状态完整可见。
- **阶段状态**：本地软件候选完成，留待下一次集中发布。尚未使用正式公众号、JS 接口安全域名或微信真机，因此不能把接口和合成响应视为真实渠道分享验收。
